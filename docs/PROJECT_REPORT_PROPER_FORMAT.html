1. Executive Summary & Project Objectives

1.1 Abstract: Blood management is a critical healthcare operation requiring rapid access to multi-facility inventory, verifiable donor medical records, and zero clinical waste of perishable blood components (42-day lifespan for red blood cells). Traditional systems relying on desktop-bound applications and relational MySQL tables encounter serious limitations regarding multi-location accessibility, deployment complexity, and rigid schema evolution. This project implements a modern, cloud-native full-stack application migrating legacy data into a cloud-hosted MongoDB Atlas database with a Node.js/Express REST API, a responsive React 18 single-page application (SPA), and an accessible semantic HTML5/CSS3 portal.

1.2 Primary Objectives:

  • Layered Separation of Concerns: Isolate presentation, business validation, and data persistence layers.
  • Clinical Safety Rules: Implement automated checks for donor age (18–65), hemoglobin levels (≥12.5 g/dL), and a 90-day cooldown between donations.
  • Perishable Inventory Management: Execute an automated First Expired, First Out (FEFO) blood dispatch algorithm to minimize product expiration.
  • Multi-Tenant Role-Based Access Control: Enforce discrete workflows for Blood Bank Staff and Hospital Representatives.

3. Cloud Database Modeling (MongoDB Atlas)

Rather than enforcing normalized SQL relational schemas that require performance-heavy joins across multiple tables, the database was designed on MongoDB Atlas utilizing Mongoose Object Data Modeling (ODM). Data structures balance embedded subdocuments (for cohesive entities) with referenced ObjectIds (for scalable relational queries):

Collection Key Attributes / Subdocuments Design Pattern & Validation Rationale
users username, password (hash), role, bankId Enumerated roles (STAFF, HOSPITAL); passwords secured with 10-round bcryptjs salting.
banks name, city, contactPhone Master branch directory supporting multi-facility blood bank operations across geographical regions.
donors name, gender, dob, bloodGroup, phones[], address{city, pincode} Embedded Document Pattern: Stores donor address and multiple phone numbers in a single document for atomic reads.
donations donorId, bankId, units, unitsRemaining, hemoglobin, screeningResult, expiryDate Referenced Pattern: Links to donors via ObjectId. Enforces screening enum (Pending, Pass, Fail) and auto-calculates 42-day expiry.
bloodrequests hospitalId, bloodGroup, units, urgency, status, issues[{donationId, unitsAllocated}] Maintains hospital emergency requests with clinical triage levels (Critical, Urgent, Normal) and FEFO allocation logs.

4. Core Module Implementation & Business Logic

4.1 Stateless Authentication & Role-Based Security (JWT)

User sessions avoid server-side memory storage. Upon authenticating at /api/auth/login, the Express server signs a compact JSON Web Token encoding user identity and permissions. Our custom Express middleware intercepts incoming requests to protected routes:

// backend/src/middleware/auth.js: Extract Bearer token & authorize role const token = req.headers.authorization?.split(' ')[1]; const decoded = jwt.verify(token, process.env.JWT_SECRET); if (allowedRole && decoded.role !== allowedRole) return res.status(403).json({ message: 'Forbidden' }); req.user = decoded; next();

4.2 Clinical Screening Engine & Medical Referential Integrity

Blood collection is strictly regulated through pure business functions in backend/src/rules.js:

  • Age & Hemoglobin Validation: Rejects intake if donor age is outside 18–65 or if laboratory Hemoglobin is < 12.5 g/dL.
  • 90-Day Cooldown: Queries the most recent donation date for the candidate donor and enforces a mandatory 90-day recovery gap.
  • Deletion Guard: Enforces medical auditability by preventing deletion of any donor with historical donation records (backend/src/routes/donors.js), preventing orphan units in inventory.

4.3 Automated First Expired, First Out (FEFO) Dispatch Algorithm

To eliminate blood spoilage, hospital requests are fulfilled via an automated FEFO query pipeline (backend/src/routes/requests.js). The algorithm searches for compatible screened units, sorts available batches ascending by expiration date ({ expiryDate: 1 }), and iteratively allocates units until the request quota is satisfied.

4.4 Real-Time Stock Aggregation Pipeline

Live inventory reporting across the 8 ABO/Rh blood groups executes natively on the database cluster using a high-efficiency Mongoose aggregation pipeline:

// Native MongoDB Aggregation Pipeline in backend/src/routes/stock.js const stock = await Donation.aggregate([ { $match: { bankId: req.user.bankId, screeningResult: 'Pass', unitsRemaining: { $gt: 0 }, expiryDate: { $gt: new Date() } } }, { $group: { _id: '$bloodGroup', units: { $sum: '$unitsRemaining' } } } ]);

5. Frontend Architecture & User Experience

The client application is architected as a lightweight, reactive Single Page Application (SPA) built with React 18 and Vite:

  • Client-Side Routing via HashRouter: Implemented with HashRouter (e.g. /#/staff/donors) to ensure robust routing on cloud static hosting platforms without requiring server-side URL rewrite configuration.
  • Centralized Session Management (AuthContext): Exposes login credentials, active roles, and JWT persistence via React's Context API and browser localStorage.
  • Custom Asynchronous Hook (useFetch): Encapsulates network communication, automatically binding bearer authorization headers, loading spinners, error boundaries, and cache invalidation.
  • 10-Second Inventory Polling: Staff live stock monitoring uses an active useEffect timer (setInterval) that polls the stock aggregation endpoint every 10 seconds with automatic cleanup on unmount.

6. Automated Verification & Testing Methodology

System reliability was verified across multiple testing tiers:

  • Postman Test Suite: Comprehensive integration test collection executing automated JavaScript assertions validating HTTP 200/201 response codes, token presence, and error payload structures.
  • Clinical Boundary Testing: Verified that attempts to record intake with Hb < 12.5 g/dL or duplicate donations within 90 days trigger HTTP 400 validation rejections.
  • Cross-Origin Verification: Validated dynamic CORS reflection in Express allowing secure cross-domain requests between Render's static frontend and API containers.
